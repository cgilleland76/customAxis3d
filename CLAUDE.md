# customAxis3d — project map

Read this first. It exists so a new Cowork session knows where it is without
Chad re-explaining the build.

## What this is

A static, no-build website for **taking 3D-print orders in person**. No
checkout, no payment processor, no card fields anywhere. Its job is to get Chad
and the customer looking at the same object, with the same numbers, before
anything goes on the printer.

Live: <https://customaxis3d.netlify.app>
Repo: <https://github.com/cgilleland76/customAxis3d>

## The public / private split — do not break this

| Public | Private (Supabase `settings`, `is_public = false`) |
|---|---|
| Product names, photos, categories, prices | Filament cost per kg, wattage, kWh rate |
| Price *bands* (already marked up) | Markup multiplier, hourly rate, flat fee |
| Grams and print time | Every cost, profit and variance figure |

`config.js` must never contain rates. `quote.html` (job costing) is owner-gated
and is deliberately absent from the public nav. Customers can submit requests
but cannot read anyone's, including their own — enforced by RLS, not by hiding
pages.

## Conventions

- Plain ES5-ish JS, no framework, no build step. One global: `APP`.
- Every cloud read/write goes through `app.js` and waits on `APP.ready`.
  Deciding on `MODE` before the client connects caused a race that made the
  live site advertise 12 demo products it did not sell.
- Failed writes go to an **outbox** and retry on the next load. Never tell a
  customer something saved when it did not.
- Demo/sample data is never substituted for an empty database.
- `schema.sql` must stay re-runnable: new columns need explicit
  `alter table ... add column if not exists`, because `create table if not
  exists` is a no-op on an existing table.
- Products carry a category **name**, written from `product.yml` by the
  pipeline. Names must match the managed list in Shop tools → Categories.
  Unlisted ones still show, grouped last and flagged.

## Testing

No runner in the repo. Sessions have verified with jsdom (load every page,
assert behaviour) and PGlite (run `schema.sql` on real Postgres, including the
upgrade path from an older database, and assert RLS negatives — anon *cannot*
read requests or quotes).

## Known open items

- Supabase `settings` table and the `quotes.actual*` columns need the current
  `schema.sql` run if the project has not had it since Aug 2026.
- Licensed characters (Disney ears, Pooh, brand logos) exist in the model
  library and pipeline. Listing them publicly on a commercial site is a
  different risk from printing them personally — worth a deliberate decision.
